# T-Lab-task1 · Автоматический поиск признаков для рекомендательных систем

**Исследование для отбора в Академию Т-Банка (задание №1).** Исходный код, выполненные эксперименты и воспроизводимый отчёт.

## 📄 Конкурсный отчёт

**[Читать полный отчёт об исследовании](research/TBANK_TASK1_SUBMISSION.md)**

В отчёте описаны постановка задачи, набор данных, ручные и автоматически генерируемые признаки, защита от временных утечек, одинаковые кандидаты, экспериментальный протокол, измеренные результаты, вычислительные затраты, честные ограничения и воспроизведение.

**Главный вопрос:** способна ли автоматическая генерация и отбор временных агрегатов пользователя, трека и их взаимодействия конкурировать с сильной CatBoost-моделью на вручную заданных признаках?

**Результат на данный момент:** подход реализован и успешно работает на реальном Yambda-50M, однако **его статистически надёжное преимущество перед ручным CatBoost пока не доказано**. Задание прямо допускает качественный отрицательный результат при корректно поставленном эксперименте.

Модель **только на затухающих признаках** выиграла **на валидации**, то есть до окончательного теста. Она получила тестовый NDCG@10 `0.16763` против `0.15819` у ручного CatBoost (**+5.97% относительно базы** на данном тестовом срезе). **Статистически устойчивое превосходство не доказано**: доверительные интервалы парных разниц для `auto` и `manual_plus_auto` относительно `manual` пересекают ноль; интервал парной разницы главной `auto_decays_only` ещё не рассчитан.

В тесте участвовало **188 пользователей с положительными действиями**; покрытие кандидатов **606 / 2 878 = 21.06%**. Эксперимент: около **2 мин 9 с**, пик **2.25 ГиБ**. Всего отработали семь методов и **21 автоматический тест**.

## Метод

Используется открытый [Yandex Yambda-50M](https://huggingface.co/datasets/yandex/yambda), в основной постановке — история прослушиваний и таблицы связей «трек–исполнитель / трек–альбом». Метка: хотя бы одно прослушивание строго более 50% трека в последующие сутки.

- История выбранных случайным образом пользователей **не обрезается**; общий временной ориентир берётся из полного Parquet.
- Признаки и кандидаты вычисляются строго по событиям `timestamp < cutoff`; целевые суточные окна train/validation/test не пересекаются.
- До 200 исторических кандидатов на пользователя получаем из популярности, повторов и переходов. Одинаковые кандидаты оцениваются всеми моделями; измеряется их покрытие.
- Ручной CatBoost использует 23 агрегатных признака, 4 косвенных признака исполнителей/альбомов и исторический ItemKNN-скоринг как дополнительный сигнал (всего **28 входных признаков**).
- Автоматический банк включает **47 признаков**: счётчики и экспоненциально затухающие статистики с разными окнами плюс пользователь–исполнитель/альбом. Важности вычисляются на обучении; размер выбранного поднабора определяется по валидации.
- Сравниваются популярность, ItemKNN, ручной CatBoost, автоматический CatBoost, их объединение, count-only и decay-only. Итоговую модель выбираем **на валидации, до чтения теста**.
- Метрики: `NDCG@10`, `Recall@10`, условные `ROC-AUC`/`LogLoss`, покрытие кандидатов, доверительные интервалы парных различий, затраты на генерацию и обучение.

**Важно:** ненаблюдаемое прослушивание не является доказанным показом или отказом от трека; кандидатные ROC-AUC/LogLoss не являются CTR. Это собственная офлайн-задача, поэтому наши значения не сопоставимы напрямую с официальными метриками leaderboard Yambda.

## Как воспроизвести

Python >= 3.11:

```bash
python -m pip install -e ".[dev]"
pytest -q

# Проверка без загрузки реальных данных
python -m tlab.experiment --demo --users 8 --snapshots 1 --candidates 24 --iterations 10 --output results/synthetic

# Исходный датасет + справочники
python -m tlab.data download --output data --with-metadata

# Реальное исследование, 100 полных историй пользователей
python -m tlab.experiment --data data/flat/50m/listens.parquet --users 100 --seed 42 --iterations 120 --metadata-dir data --output results/yambda-100

# После первого успеха — 1 000 полных историй
python -m tlab.experiment --data data/flat/50m/listens.parquet --users 1000 --seed 42 --iterations 120 --metadata-dir data --output results/yambda-1000
```

Данные и результаты не сохраняются в Git. Каждый эксперимент создаёт `metrics.json`, `feature_selection.json`, `run_config.json`, `REPORT.md`.

**GitHub Actions запускаются исключительно вручную** и содержат проверку тестов перед скачиванием датасета:

## Что уже готово и чего не хватает

| Критерий задания Т-Банка | Статус |
|---|---|
| Базовая задача, воспроизводимый CatBoost и ручные признаки | Реализовано, протестировано на настоящих данных |
| Алгоритмический генератор/отбор признаков | Реализовано и протестировано |
| Честное сравнение, тайм-сплиты, выбор по валидации и замеры затрат | Реализовано; требуется больше независимых проверок |
| Разбор результатов и ограничений | [Отчёт с измерениями и выводами](research/TBANK_TASK1_SUBMISSION.md) |

**Основные ограничения:** в основном тесте покрытие кандидатов 606/2 878 = 21.06%; 188 пользователей с положительными метками; один тестовый день и одна когорта; превосходство не подтверждено парным доверительным интервалом для выбранной decay-only модели; ItemKNN пока не расширяет кандидатов; ALS/SASRec не сравнивались по нашему протоколу.

Следующая оправданная проверка — повторить оценку на **других временных срезах/когортах** и расширить кандидатный поиск; запуск на 1 000 пользователях текущего кода **уже подтверждён**. Изменения после просмотра тестовых оценок следует проверять на новой независимой выборке.

## Независимый аудит перед сдачей — 25.10.2026

**[Читать итоговый аудит научной идеи, опубликованных решений, кода, ошибок и ограничений](research/FINAL_INDEPENDENT_REVIEW_2026-10-25.md).**

После подтверждённого запуска на 1000 пользователях были улучшены **только** расчёты парных bootstrap-интервалов (включая validation-selected `auto_decays_only`), обозначение `@K` метрик, регрессионные тесты, возможность выбрать независимую когорту в ручном workflow и документация. **Обучаемые модели, их признаки и основная выборка кандидатов не менялись.** Старые значения NDCG/Recall остаются значениями исходного запуска, но **новые CI и тесты требуют повторного CI**; старую зелёную галочку нельзя считать его проверкой.

Для следующего исследовательского повтора: сначала [Manual tests](https://github.com/voityvaity/T-Lab-task1/actions/workflows/manual-tests.yml), затем [Manual Yambda research](https://github.com/voityvaity/T-Lab-task1/actions/workflows/manual-yambda-research.yml) с `users=1000`, `iterations=120`, `seed=137`. Это **другая когорта того же тестового дня**; временной сдвиг следует исследовать отдельно. Подбор по уже просмотренному тесту недопустим.
